# topk — 边缘安全网关 Top-50 拦截源统计

纯内存统计组件：返回近 24 小时（当前分钟 + 之前 1439 个完整分钟）内被拦截
次数最多的至多 50 个源 IP。进程重启后统计清零。

## 设计

- **每分钟一个 Space-Saving 摘要**（容量 1000）。该摘要保证每分钟内任意
  IP 的估计计数与真实计数相差 ≤ N_i/1000（N_i 为该分钟拦截总数），且
  计数总和恰好等于 N_i。摘要用定长数组存储，可变期内配一张 IP→槽位
  映射和一个最小堆做 O(log n) 淘汰；分钟封存后映射与堆即释放。
- **一张全局合并哈希表**（开放寻址、线性探测、后退式删除，固定 2^21
  槽）实时维护所有存活分钟摘要的逐 IP 求和：Record 时随分钟摘要的
  增加/淘汰同步增减，分钟过期时整批减去。因此窗口估计误差
  ≤ ΣN_i/1000 = N/1000，确定成立，与输入分布无关。
- **分钟环形缓冲**（2048 个槽位）按分钟号取模复用；存活分钟最多
  1443 个（窗口 1440 + 迟到宽限 2 + 当前），不会误清。
- **迟到记录**：当前分钟与前 2 分钟保持可变，迟到 ≤2 分钟的记录计入
  其所属分钟，并随该分钟一起过期；更晚到的直接丢弃。
- **过期**：窗口滑动时按分钟精确从合并表中减去过期摘要；若 `now`
  一次性跳过整个窗口则整体清空。边界精确到分钟，无衰减、无近似淡出。

### 保证（对任意输入序列确定成立）

设窗口内真实计数从大到小第 50 名为 t50（不足 50 个 IP 时为 0）：

1. 返回的每个计数与真实计数相差 ≤ N/1000（N 为窗口拦截总数）。
2. 真实计数 > t50 + N/500 的 IP 一定出现在结果中。
3. 结果中每个 IP 的真实计数 ≥ t50 − N/500。

证明要点：合并估计误差 ≤ N/1000（每个方向）。若某 IP 真实计数
> t50 + N/500，则其估计 > t50 + N/1000；而估计超过该值的 IP 至多
49 个（否则至少有 50 个真实计数 > t50），故必在前 50。同理，估计第
50 名 ≥ t50 − N/1000，故返回的每个 IP 真实计数 ≥ t50 − 2N/1000
= t50 − N/500。

## API

```go
tr := topk.New()
tr.Record(ip, ts)   // ip: netip.Addr, ts: Unix 秒；可并发调用
top := tr.Top(now)  // now: Unix 秒，单调不减且不小于任何已记录的 ts
```

## 复杂度与资源

- 内存：约 88 MiB（GC 后堆），与不同地址数无关；不保存原始记录。
- Record：均摊 O(1)，最坏单次（跨分钟边界）实测 0.29 ms。
- Top：O(表大小) 扫描，满窗口实测最大 9.8 ms。
- 吞吐：单 goroutine、每条全新地址的最坏输入下实测约 360 万条/秒。

（以上实测于 Apple M1 Max；指标由 `BenchmarkRecordWorstCase` 与
`BenchmarkFullWindow` 报告。）

## 测试

```sh
go test ./...                 # 全部正确性测试（含千万级洪水对照）
go test -race -run TestConcurrentSmoke .
go test -run '^$' -bench . -benchtime 2s .
```

- `TestFlood`：1500 分钟（25 小时）、约 1500 万次拦截，绝大多数为只
  出现一次的随机 IPv6 地址，混入 80 个强度与活跃时段各异的打击者；
  以精确计数作对照，在 30 余个 now 上逐条核对三条保证。
- `TestWindowBoundary`：最强打击者仅在窗口最早一分钟 vs 再早一分钟，
  前者必须在结果内且计数满足误差界，后者必须不出现。
- `TestLateRecords`：整点前后迟到 1–2 分钟的记录计入正确分钟并随之
  过期；超过宽限期的记录被丢弃。
